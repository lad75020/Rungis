## Core technical evidence

- `backend/src/server.js` creates a Fastify application, connects Redis and MongoDB, migrates legacy app settings into SQLite, registers cookie, form body, JWT, session, websocket, EJS view, static file, security-header, route, and health-check functionality.
- `backend/src/server.js` serves static files from `backend/src/public` and serves Angular build output from `backend/src/public/angular`.
- `backend/src/lib/runtime-config.js` loads server configuration from environment variables and development fallbacks.
- `backend/src/lib/http-security.js` adds a per-request CSP nonce and content security policy.
- `backend/src/lib/app-settings-store.js` stores application settings in SQLite through `node:sqlite` and migrates older MongoDB `appsettings` records when present.
- `backend/src/routes/index.js` contains shared helpers, role guards, validation helpers, billing generation, association management, realtime broadcast helpers, and route-context assembly.
- `backend/src/routes/modules/*.js` split the registered surface by auth/account, management/statistics, pages, bills/PDF export, refunds, and websocket API actions.
- `frontend/src/app/app.ts` is the Angular standalone application component. It uses signals and fetch/WebSocket calls to drive all pages inside the single app shell.
- `frontend/src/app/app.types.ts` defines the frontend contracts for sessions, carts, statistics, bills, reminders, catalog items, and websocket responses.
- `frontend/src/app/app.constants.ts` defines supported pages, languages, roles, and the empty cart value.

## Business behavior evidence

- Account lifecycle uses `User.isActive`; vendor and client subscriptions are inactive until admin approval.
- Users have roles `vendor`, `client`, or `admin`; signup only permits vendor and client roles.
- Vendor-client assignments are stored symmetrically on `User.vendorIds` and `User.clientIds`.
- Merchandise belongs to a vendor, has category, reference, price, stock, optional image, and optional low-stock threshold.
- Active carts are stored as Redis JSON keyed by client and delivery date; a Mongoose `Cart` model exists but the active cart path uses Redis helpers.
- Validating a cart creates `ValidatedOrder` records, freezes line prices, and decrements stock.
- Daily bill generation groups validated orders by UTC day plus vendor/client pair, adds unapplied refunds, upserts `Bill` documents, and marks newly applied refunds.
- Bills track vendor and client settlement independently.
- Refund lines are negative bill lines and refund comments are limited to 32 characters.
- Penalty lines use a percentage constrained between 1 and 50, and the UI/business flow applies a single penalty line per bill.
- Overdue bills use the SQLite `billOverdueDays` app setting, defaulting to 30 when unset or invalid.
- Global style profile uses SQLite `appStyleProfile`, normalized to `primary` or `secondary`.
- WebAuthn/passkeys are stored on the user document and use SimpleWebAuthn server/browser packages.

## Evidence gaps and constraints

- The repository does not define SDD API contract files. Therefore `.sdd/docs/api-reference.md` was not generated from contracts. A runtime route inventory was created instead as `.sdd/docs/runtime-api-inventory.md` and is explicitly implementation-derived, not a contract.
- The repository does not define Docker or CI deployment artifacts. Deployment documentation therefore describes manual deployment from actual npm scripts and calls out missing automation.
- The repository path is not available as a git worktree with the default discovery boundary, so final git status could not be used as the only change inventory.
- The backend `.env` file exists but was not read to avoid copying local secrets. Documentation uses `backend/.env.example` and `runtime-config.js` only.
